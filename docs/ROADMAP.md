# 길동무 작업 스케줄 (새 세션이 먼저 읽는 파일)

어르신용 대중교통 길안내 도우미. 무료 웹앱으로 시작해 나중에 플레이스토어 앱으로 낸다.
앱 주소: https://keumuek7-glitch.github.io/gildongmu/ (main에 합치면 GitHub Pages 자동 배포)

## 큰 순서

1. **A 버전** (진행 중, 실사용 단계): 자녀가 어르신 위치+방향을 보내면 어르신 앱이 그 자리 로드뷰를 띄움.
2. **앱으로 감싸기**: 안드로이드 앱(플레이스토어). 먼저 TWA(Bubblewrap)를 추천. 아직 시작 안 함. 구글 개발자 계정(25달러, 1회)과 앱 서명 키가 필요. 서명 키·비밀번호는 저장소나 채팅에 올리지 않는다.
3. **B 버전**: GPS 추적 + 경로 이탈 경고. 이때 Capacitor로 바꾸는 것을 검토.

## 길찾기 방침

- 당분간 C안: ODsay/카카오 호출을 저장하고 하루 상한을 둔 채로 시험.
- 최종은 A안: 서울시 공공자료로 앱이 직접 계산.
  - A안 1단계(지하철): 완료 (#11, 매월 자동 갱신 #13).
  - A-2 2단계(1km 안쪽 도보): 완료 (#14). 도보 시간 × 1.45 보정.

## 정한 디자인 규칙

- 한 화면에 할 일 하나, 글자 한 줄, 큰 글씨. 어르신 화면은 버튼 2개 이하(가족 화면은 예외).
- 어르신 모든 화면 우측 상단에 빨간 정사각형 SOS 전화 버튼. 질문은 최대한 줄이기.
- 화살표(➡ 등)는 쓰지 않고 방향은 역·정류장 이름으로 확인.
- 가족 화면 "한 마디 고르기" 문장 버튼 4개: 2줄×2칸, 1:1, 가운데 정렬.
- 방향 색: 목적지 쪽=초록(#15803d), 왼쪽=하늘색(#0ea5e9), 오른쪽=주황(#f97316). 가족이 보낸 색은 안내에 담겨 어르신 화면·나침반에도 적용. 색 정보가 없는 예전 안내는 초록.

## 작업 규칙 (자세한 건 CLAUDE.md)

- main에 직접 푸시 금지. 작업 브랜치 → 초안 PR → 사용자 승인 후 Squash and merge 1회.
- 머지 전 확인: `npm test`, `npm run typecheck`, `VITE_BASE=/gildongmu/ VITE_STATIC_DEMO=true npx vite build`, `npx vite preview --base /gildongmu/ --host`.
- 새 세션에서는 `npm ci`가 먼저 필요할 수 있다.
- 5분 이상 걸리는 작업은 실행 전에 묻기. API키가 외부로 나가면 경고.

## 알려진 빈틈

- "버스 보행 거리 작업"은 이전 대화에서 이름만 나왔고 구체적인 내용이 기록되지 않았다. 정류장까지 걷는 거리 표시 / 버스 길안내에 걷는 구간 넣기 / 너무 먼 도보 경로 거르기 중 무엇인지 정해지면 여기에 적는다.
- ODsay 응답 형식은 실제 응답으로 검증하지 않았다(README 참고).
